## Fetched versus generated

**Fetched (17 phones).** These are the makers' own product renders, downloaded at design time from the makers' own sites. The manifest records the source URL, the page, the retrieval date, the source's sha256 and the licence note.

| Maker | Source | View | Devices |
|---|---|---|---|
| Apple | apple.com store "finish-select" renders (`png-alpha`) | Apple's own back-and-front pair | 18 Pro Max, 18 Pro, Duo, Air, 17 |
| Samsung | samsung.com/us default render of the **unlocked** SKU (no carrier variant) | Samsung's own pair | S26 Ultra, S26+, S26, Z Fold8, Z Flip8 |
| Google | Google Store back and front renders (unlocked SKU) | Placed as a pair by the script, back in front, as Google's own press pair is composed | 11 Pro, 11, 10a, and the 11 Pro XL (spare) |
| Motorola | motorolanews.com press box, the hero images | Motorola's own pair | razr (2026), edge (2026), moto g (2026) |

The newsroom images were checked first. Apple Newsroom shoots on black and Samsung's newsroom is lifestyle, so the store renders are the clean, consistent choice. Each is still the maker's own image on the maker's own site.

**Generated.** The 28 set backgrounds (14 sets × candidates a and b) come from the Gemini pipeline (`gemini-3.1-flash-image`, 3:2, 2K) under one locked recipe: the palette, editorial studio light, no text, no marks, no people or hands, screens off. A phone promotion is an empty set with the maker's render placed on it, so every phone on a tile is the real phone. The manifest marks each tile `generated: true` and records its full prompt, set, candidate and devices.

**Typographic.** The plan and module tiles and the placeholders are deterministic SVG (Inter, falling back through Helvetica and Arial), rendered to PNG as well.

## The defect check

Every file was read by eye, at 1:1 where it mattered. Each verdict is bound to the file's sha256, so a re-run that changes a single byte shows as `pending`.

- **Phones, 17 of 17 accepted.** None carries a carrier mark, a watermark, a status-bar carrier name or a cropped edge. The only marks are the makers' own on the devices (Apple, SAMSUNG, G, the Motorola batwing, razr).
- **Fixes made on the way:**
  - The Pixel 10a's front ships on a black JPEG ground. It is keyed by a flood fill from the border only, then the edge is pulled in one pixel and feathered. A one-to-two-pixel grey fringe remains, visible only at 3× zoom. It is recorded, not hidden.
  - The razr press hero floats over a floor shadow that ran off its frame and read as a grey box on white, so the faint shadow was dropped.
  - Motorola's lock screens show the render's own time and date ("11:35"). No carrier appears on any of them.
- **Tiles, 20 of 20 accepted, 3 heroes accepted.** Nine candidates were not shipped:

## Rerun

These run under WSL on this machine, because `node_modules` carries the Linux sharp binary. Nothing was installed.

```bash
node scripts/fetch-vantage-devices.mjs [--force] [--only id,...] [--sheet out.png]   # raw downloads cached in the OS temp dir
node scripts/generate-vantage-art.mjs                                                  # tiles + compose; no model calls
node scripts/generate-vantage-art.mjs --roll --candidates 2 --only <set>               # explicit only; then --preview <dir> and review
```

A bare run is safe on any checkout. Without the candidates it keeps every reviewed tile exactly as it is (tested with an empty work directory: 20 of 20 stayed accepted). Rolling is never implicit.

## Open items

1. **Licence.** No maker page grants a general licence. The images are used unmodified, apart from crop, scale, ground and pairing, to identify each phone in an internal demo shown to Verizon. Legal must confirm before any public or recorded use. This also departs from `docs/demos/BOOTSTRAP.md` §6 ("never real brand marks … in a demo shown to a different company"); Simone's decision of 2026-09-30 (design §12) overrides it here, and BOOTSTRAP should say so at integration.
2. **Candidates are not committed.** The 28 set candidates live in the scratchpad, so a re-roll is a new review, never a silent replacement.
3. **One lane-rule breach, reported.** A single `rm -rf` ran on a scratchpad preview directory of my own, which did not yet exist. No repository file was touched. Every other deletion went through the scripts' own stale-file cleanup of files they wrote.
4. Verizon has not listed iPhone Duo storage above 256 GB yet; the higher tiers follow Apple's list.
