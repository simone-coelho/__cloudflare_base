## 2. The documents (tenant `vantage`)

- **Registry**: eight dimensions; `priceBand` cut at 400 / 900; K 1.8, θ 0.60 / 0.45; memory compressed for this room and labelled so (`brand`, `contentType` 60 s; `priceBand`, `intent`, `perk` 10 min; the rest 14 days); `select`, `filter`, `compare` weigh 2.
- **Catalog**: 17 promotions at real magnitudes, 4 heroes, 7 modules, 4 plans. The Duo pre-order is gated to `new`, `add-line`, `upgrade`, so it never reaches someone bringing her own phone; the watch-and-tablet line is open to `byod`, so that four stays full.
- **Slots**: `deals` takes 4, two per brand, with L4's seeds and three calibrated dials: promotion 0.1 (L4), **intent 1** (declared intent is the carrier's merchandising axis) and **lines 0.4**. **Slot weights must lie between 0 and 1** (`src/content/kinds.ts:324`); the bootstrap refuses 1.5 with a 422. At 1 the lines-tagged offers held the four from beat 9 on.
- **Learn**: holdout 0, `regional { enabled, kBlend 0.5, minEvents 30 }`, γ 0, exploration off.

## 3. The route

404 unless `DEPLOYMENT_PROFILE` is `demo`; every call sends `X-Tenant: vantage`. `POST /beat { name }` publishes one of five assets with a 60-second minted operator token; `POST /reset` republishes the open documents; `POST /receipt { decisionId | decisionIds }` returns the shopper's own records through the audited ledger read (202 while pending), with asserted `ctx.intent` and `ctx.region`; `POST /report { date, slot }` gives attribution per slot and item. The page links the phone page as `/vantage/phone?id=<id>`, which the assets binding serves. The path form `/vantage/phone/:id` is retired (lane F1, after R1 N7): a browser navigation to it gets the single-page fallback, and `run_worker_first`, which would have changed that, made local POSTs answer 405.

## 6. Findings

2. **`pdp_view` is refused**; phone pages send `product_view` with `view: 'page'`. The receipt needs `IDENTITY_SALT` and D1 migrations 0010–0013.
3. **Engine findings, no engine change.** The first and the third point at the owner forwards in `src/identity/sessionAuthority.ts`.
   - **The object host stalls the ledger consumer** after 20 to 40 quick snapshots (`ledgerUnderOwners`, line 178), so the worker runs the session host and the alarm push stays behind `?exit=1`.
   - **The session host's consumer stalled too, once, locally**, after about four hours and several thousand decisions: every receipt answered 202 while queue batches still acked. Cause unknown. A restart on the same state cleared it (a receipt in 3.9 s, the report 200).
   - **Session-host meter reads occasionally stall.** 4 of 771 reads took over 1 s (15.8, 15.3, 7.8, 2.0 s); none of 671 events did, and 200 controlled reads reproduced none. Quiet reads run at 20 ms; the `listPublished()` N+1 sits on the event path (`AudienceStore.ts:49`), not the read. The unconfirmed lead is `ownerFetch`'s 5 s abort (line 299): 15 s is three of them.
4. **Outside the seeded regions the prior falls back to the country trend**, built by this worker's own rehearsal traffic. The cold-start route reads `?region=`.
