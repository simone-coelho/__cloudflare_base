## 3 · What the audit got wrong

1. **The finding's own title names "the event engine" and the evidence never cites it.**
   `src/services/RealtimeSegmentEngine.ts` — the live event engine on all three environments — does
   not appear once. Its `processActionEvent` (`:406-410`) resolves surface → config → catalog →
   audience prefix; `:469` fans the regional prior under the surface; `:375` seeds audiences with no
   tenant. The audit cites the *dormant* `ShopperReflex` for exactly these two defects and misses the
   live host that has them identically.
2. **Two of nine citations are on a path disabled by configuration.** `ShopperReflex.ts:555` and
   `:1084` are gated behind `REFLEX_HOST === 'do'`; `wrangler.toml` sets `"session"` in dev, staging
   and production, and brief §6 says stamps stay there. Correct as code, not currently executing.
   The audit does not say so, and a reader would over-weight them.
3. **"Two registries" undercounts.** There are **four** scope axes in play: (a) the path/`?scope=`
   `ConfigScope` (`routes/decisions.ts:335`, `routes/config.ts:44-46`); (b) the middleware tenant
   (`c.get('tenant')`, passed as `stateTenant`); (c) the demo surface; (d) `TREND_ROLLUP_TENANTS`.
   `serveContentDecisions` alone straddles (a) and (b): catalog/slots/learn/config/trend/lift/ring use
   `r.tenant`, while shopper state and session use `r.stateTenant`. `routes/decisions.ts:332-334`
   calls this "two names, on purpose".
4. **Minor line drift.** `registry.ts:68` is the signature; the Coach default is `:78`.
   `odpLoop.ts:331` is the object literal opener; the Coach attributes are `:333-336`.
5. **`src/demos/registry.ts` is not a "customer registry".** It is a demo-surface registry, and the
   builders documented the split as deliberate (`connectors/AudienceStore.ts:37-41`: "Surfaces are
   pseudo-tenants and should eventually become real ones, but converging them now would break both
   demos for no gain"; `reflex/configStore.ts:46-51`: "CW1 (multi-tenancy) makes it
   `{tenant}:{surface}`"). The defect is real; the framing is imprecise, and precision matters
   because the fix is *thread the tenant*, not *delete the demo registry*.
6. **Nothing is overstated.** If anything the consequence is soft: the audit says a ten-brand
   deployment "can silently use Coach dimensions"; it does, unconditionally, and its own authored
   audiences are dead on arrival.

## 4 · What the audit missed

1. **`src/connectors/index.ts:27` — the single highest-value line in this finding.** One default
   parameter makes audience qualification Coach-only on every path, on the live host. Uncited.
2. **`ensureAudiencesSeeded`'s tenant parameter is dead code.** It exists, it is typed, and no
   production caller passes it (probe C).
3. **The operator console and the engine disagree about the audience store** (probe F). This is the
   most legible customer-visible symptom and is not in the audit.
4. **`src/identity/link.ts:110`** repeats `history.ts:105` in identity stitching — same shape,
   uncited.
5. **`src/routes/sort.ts:76`** — the third surface resolution in that file, on the *live* session-host
   branch. The audit cites only the dormant DO branch (`:70`) and the outer one (`:90`).
6. **`odpLoop.ts:109-121`** resolves every event's product through a bare `new CatalogService()` —
   the compiled Coach catalog — for every tenant. **`odpLoop.ts:38-44`** hardcodes five Coach audience
   names as the GraphQL subset. Both are Coach hardwires in the same file as the cited `:331`.
7. **The demo surface is caller-controlled and not key-gated.** `surface` is an optional field on the
   action-event schema (`routes/realtime.ts:74`). The SDK-key gate validates the *path tenant*
   (`middleware/edgeAccess.ts:122`); nothing validates that a surface is legal for that tenant, and
   nothing prevents a tenant id from colliding with a surface name.
8. **A test that passes for the wrong reason.** `src/tenancy/storeIsolation.test.ts:156-163` —
   "an unconverted caller still works, because CW1 lands store by store … a store built without a
   tenant is the default tenant" — **codifies the silent Coach fallback as correct**, which is
   precisely why `getConnectors(env)` can never be caught by the isolation suite. 43 tests green
   across the two relevant suites while every divergence is live.
9. **The claim this refutes is not named.** `docs/architecture/20-scope-truth-ledger.md` row 3 marks
   §1.7 "multi-brand provisioning with hard data isolation" **CLOSED 2026-09-03 (CW1)**, asserting
   "Isolation is proven with pairs that cannot pass by accident … which is how the last half-conversion
   was caught". F31 is the evidence that row 3 must be reopened. Brief §6 does not disclose this;
   §5 item 12 asserts multi-tenancy as delivered.

## 7 · Remedy assessment

The audit's remedy is **directionally right and over-scoped for the immediate need, and it omits the
two cheapest, highest-value edits.** A canonical brand configuration owning taxonomy, providers, event
schema, journey/decay, identity policy, consent, connectors, experiments and exports is the correct
end state and the two-non-default-brand proof is exactly the right acceptance test — the repo's own
`storeIsolation.test.ts` already proves that only non-default pairs can fail. But the remedy is
written as a redesign, and four of the six live defects are a dropped argument at a call site that
already holds the tenant.

"Demo surfaces become explicit fixtures/adapters with no silent production fallback" is the right
instruction, and the mechanism should be named: `resolveSurface()` must not be reachable from any
`/v1/:tenant/*` handler.

**Smallest safe fix.** There is no launch-blocking part to close: Coach is the default on every axis.
The smallest safe fix that closes the *false closure* and the worst silent failure is roughly two
engineer-days:

1. `getConnectors(env, tenant: TenantId = DEFAULT_TENANT)` → `new KvAudienceStore(env, tenant)`, and
   pass the tenant at the call sites that already have it: `content/service.ts:112`,
   `routes/sort.ts:74`, the nine sites in `routes/realtime.ts`.
2. `RealtimeSegmentEngine.ensureSeeded` → pass `this.tenant` as the fourth argument to
   `ensureAudiencesSeeded` (`:375`).
3. `RealtimeSegmentEngine.ts:469` → `tenant: this.tenant`, not `tenant: surface`.
4. `identity/history.ts:105` → resolve the config from the `tenant` parameter already in scope.
5. Reopen doc 20 row 3 and add one isolation test that runs a decision and an event under two
   non-default tenants and asserts the config scope, the audience keys and the trend key all carry
   the tenant. **Write it first; it must fail on today's HEAD.**

Deferred to the L remedy, correctly: the `ShopperReflex` half (the DO does not know its tenant — the
name carries it but the DO cannot read it back, so the tenant must ride the ingest request), ODP
identity scoping and per-tenant credentials, the Coach-hardcoded ODP attributes and mirrored audience
names, unifying path-scope with middleware-tenant, and folding `TREND_ROLLUP_TENANTS` into
`tenantConfig().provisioned`.
