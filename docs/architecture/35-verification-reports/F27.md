## 4 · What the audit got wrong

1. **Duplicate-tag inflation is not reachable through the feed.** `normalizeTags` (import.ts:16–30) already deduplicates via `new Set`, on both the object and the `dim:a|b` string forms. The consequence sentence — *"duplicate/misspelled tags validate… malformed taxonomy can suppress or inflate scores"* — reads as a property of the import path. Inflation is reachable **only** through a raw `PUT /content/catalog`. The remedy's *"deduplicate tags"* therefore belongs in `validatePiece`, not in "one canonical normalizer". Suppression (a misspelled dimension scoring 0) does happen on both paths.

2. **The remedy would break the one path that currently works.** *"One canonical schema/normalizer for JSON, CSV, pull, and direct PUT"* — `pull` already reuses the JSON normalizer (`routes/content.ts:173` → `recordsFromJson` → `candidatesFrom`), so only three paths exist, and direct PUT deliberately bypasses the normalizer. That bypass is why `scripts/seed-coach-content.mjs` preserves the Coach promotions today. Funnelling PUT through `normalizePiece` as written would *cause* the data loss on the only path that is currently correct. The right shape is: make the normalizer lossless against the validator's accepted field set, then prove it with a round-trip test.

3. **The brand/locale claim is overstated as evidence.** *"Brand/locale/slot-eligibility language in the customer schema is not automatically satisfied by `slotTypes` and geographic affinity"* carries no file citation and is argued from documents. **Brand is handled** — the catalog is stored per scope (`scopeOf`, routes/content.ts:42), one catalog document per tenant:brand. **Locale/market genuinely have no field** anywhere on the piece, and that half stands. The customer's own paper (`docs/architecture/tapestry_requirements.txt`) names multi-brand rollout but no locale eligibility field, so this is a portability gap, not a missed customer requirement.

4. **Blast radius on the stage words is narrower than implied.** `docs/kit/03-payload-schemas.md:117` — the document the PS guide itself declares authoritative at `:107` — states the vocabulary correctly. One internal sentence is wrong, not the documentation set. It still matters: the PS guide is what a consultant reads when telling a content team how to tag.

Nothing else is wrong. No line drifted; no consequence was invented.

## 5 · What the audit missed

1. **A feed refresh resurrects retired content.** `normalizePiece` (import.ts:71) always emits `lifecycle: { status: status ?? 'live' }`, and `assemble` (import.ts:148) replaces the whole piece. Reproduced: a stored piece with `lifecycle.status: 'expired'`, a closed `window`, `art` and `merchandising: {promotion: 1}` was refreshed by a feed row that omitted `status`, and came back as
   `{... "lifecycle":{"status":"live"}}` — no window, no art, no merchandising.
   An expired campaign returns to the hero, with its stop date deleted. This is a **worse governance failure than the boost loss** and belongs in its own row; it also overlaps F28's pin/governance territory.

2. **A tag-less feed validates and silently zeroes the catalog.** A JSON or CSV export with no `tags` field yields `tags: {}` on every piece, passes `validateContentCatalog`, and returns `ok:true`. Every score is 0 and every slot falls back to catalogue order. Reproduced with a five-column CSV: `every piece tags = [{},{}]`, `valid? true`.

3. **The CSV header is case-sensitive where the rest of the adapter is forgiving.** A header of `Tags` instead of `tags` produces the same silently-empty taxonomy (`valid? true tags = {}`), while `stockOf` cheerfully accepts `Y/N/0/1/sold_out`. Reproduced.

4. **There is no warning channel at all.** `importInto` returns counts only (routes/content.ts:134–137). Nothing tells an operator that a field was ignored, a dimension is unknown, or a taxonomy came back empty. Every failure in this finding is silent by design, which is why the audit needed probes to see them.

5. **Per-piece `merchandising` has no authoring surface whatsoever.** `public/console/views-config.js:366–370` edits the **slot's** weights; `public/console/` has no content-catalog editor at all. So the signals are unreachable by import, by CSV, by pull, and by console — the only way to set them is a hand-authored full-catalog PUT. That is a stronger statement than "import strips merchandising", and it changes the remedy: preserving the field in the normalizer is necessary but not sufficient for a merchandiser to use it.

6. **The test that passes for the wrong reason.** `src/content/freshFatigue.test.ts:112` and `src/content/inventoryDiversity.test.ts:83` are both titled *"the import adapter carries the BTIE names through"* and cover four of the five optional piece fields. `src/content/merchandisingSeam.test.ts:77–80` covers `merchandising` — but through `validateContentCatalog` only. No test crosses the seam where the defect lives. Worse, `src/content/import.test.ts:22` **positively asserts** that an unknown field is stripped (`expect(...vertical).toBeUndefined()`), and every piece assertion uses `toMatchObject`, which by construction cannot fail on a missing field. `npx vitest run src/content/import.test.ts src/content/merchandisingSeam.test.ts src/content/kinds.test.ts src/routes/content.test.ts` → **26 passed**.

7. **The scope-truth ledger records this as closed.** `docs/architecture/20-scope-truth-ledger.md:37` (row 6, scope §1.5) reads *"Closed 2026-09-04 (code) … the signals on the piece (`merchandising: {season, promotion, margin}` in 0..1, validated with the catalog)"*. True of the validator and the decision path; false of every ingestion path a customer would use. And `docs/kit/00-README.md` claims *"every request and response in these pages was executed against the code before it was written down"* — the `merchandising` row of kit 03 was not executed through the CSV or import path.

8. **Case-variant tag values survive both paths** (`'Drover'` vs `'drover'`) and score 0 against the affinity vector. A second, quieter way a taxonomy suppresses scores; no normalization, no warning.

## 7 · Remedy assessment and the smallest safe fix

**Assessment: right diagnosis, over-scoped remedy, and one instruction that would do harm.** The remedy correctly identifies lossless normalization and round-trip verification as the fix. It then bundles three separable pieces of work — registry validation, brand/locale/market eligibility, and D5 product-attribute inheritance — into one M estimate, and its first clause ("one canonical normalizer for … direct PUT") would, taken literally, route the only currently-correct path through the lossy code. Split the row.

**Smallest safe fix that closes the pilot-blocking part** (about half a day, no schema change, no contract change):

1. `src/content/import.ts` — in `normalizePiece`, carry `merchandising` when present, keeping only the three known terms as finite numbers and letting `validatePiece` reject anything out of 0..1 (a bad feed must still 422, not be silently coerced). Add a `dim:value;dim:value` cell parser for it and add `'merchandising'` to `CSV_COLUMNS` (import.ts:130).
2. `src/content/import.ts:71` — do **not** default `lifecycle.status` to `'live'` in merge mode; carry the field only when the feed states it, and preserve the stored `lifecycle` and `window` for a known id. This stops retired campaigns from being resurrected by an incomplete refresh.
3. `src/content/kinds.ts:25` — add `explore → exploring`, `consider → considering`, `decide → deciding` to `stageWordOf`. Three lines, backward compatible, and it makes the PS guide's sentence true rather than requiring the customer's own A.3.6 vocabulary to be renamed before ingest.
4. `src/content/kinds.ts:47` — `tags[dim] = [...new Set(vals)]`. One line; closes the direct-PUT inflation path the probe measured at 3×.
5. One new test — a single fixture carrying every field in `docs/kit/03-payload-schemas.md` "The content piece", asserted to survive JSON import, CSV import, `HttpJsonSource` pull, and direct PUT, plus a merge-refresh case asserting `lifecycle`, `window` and `merchandising` are preserved. This is the test that would have caught the finding and the one that keeps it caught.

**Deliberately left out of the small fix, to be tracked as their own rows:** active-registry membership validation (needs the `DocumentKind.validate` signature to see `ReflexConfig.dimensions` — M); brand/locale/market eligibility as a first-class gate independent of affinity (M–L, and a real portability gap for the next customer); a per-piece merchandising authoring surface in the console (S–M, but without it the field stays operator-hostile); and D5 — either implement product-attribute inheritance or narrow the commitment in writing to linkage and attribution, which is all `decide.ts:265` and `fan.ts:63` actually do, and all `docs/architecture/21-tapestry-gap-closure-plan.md:143` actually claims. `docs/architecture/26-btie-requirements-gap-review.md:118` is the sentence that overpromises ("so content inherits product affinity"); the cheapest honest close is to correct that line with customer agreement.
