Three things this establishes beyond the audit's text: the payload carries a **behavioural profile**

### R3 — "off" is genuinely off (CONFIRMS the audit's "default deterministic mode honors the intended shape")

* `external` configured but every slot at `weight: 0` → **0** outbound fetches.
* `DEFAULT_LEARN` (`src/content/kinds.ts:376–385`) has no `external` key.

### R4 — `Promise.race` gives up; it does not cancel (CONFIRMS the audit's sharpest sentence)

`scoreExternal` with `timeoutMs: 10` against a 250 ms "model":

```
R4 scoreExternal returned after 10ms: {"ok":false,"ms":10,"reason":"timeout after 10ms"}
R4 at return:   started=1 finished=0
R4 400ms later: started=1 finished=1   <-- upstream work completed anyway
```

`grep Abort src/learn/external.ts` → **0 occurrences**. `src/learn/external.ts:106–108` builds a
`setTimeout` promise and races it; the losing promise runs to completion. The audit's "a `Promise.race`

### R5 — what the shipped validator will accept as a "model"

`validateLearnConfig` (`src/content/kinds.ts:302–312`) returned `ok: true` for:

— plaintext scheme, arbitrary host, and a **5000 ms** budget on a decision path whose stated P95 target is
under 200 ms (brief §6). `kind: 'workers_ai'` with any model id is likewise accepted.

### R6 — the holdout default arm suppresses the call

`holdout.share: 1` → `arm: 'default'` → 0 outbound calls. `service.ts:197` and `decide.ts:88` agree.

### R8 — the size of what is sent, per decision

`{id, tags}` over six tag dimensions, JSON body length:

| catalog pieces | body per decision | per 1,000 decisions |
|---|---|---|
| 26 | 6.0 KiB | 6.2 MB |
| 200 | 45.0 KiB | 46 MB |
| 1,000 | 224.3 KiB | 230 MB |
| 5,000 | 1.09 MiB | 1.15 GB |
| 20,000 | 4.38 MiB | 4.59 GB |

Doc 31 §3 sizes the design at a million decisions a day. At a 1,000-piece catalog with one weighted slot

reachable for a body of that size. This is the quantitative half of the audit's "send only eligible
bounded candidates".

### What could not be reproduced locally

Whether any live stamp currently has `learn.external` set. That requires reading the staging or production
KV store, which is a network call and out of scope for this verification. Nothing in the repository —
`DEFAULT_LEARN`, `scripts/`, any seed JSON — sets it, so the honest statement is: *off by construction in
the repository; unattested on the running stamps.* Confirming that is a one-command read of
`GET /content/learn` per stamp and belongs in the remediation.

## 3 · Severity and size

**I agree with "blocks the pilot."** The brief's own scale (§1 of the audit, and the brief's four labels)
permits optional model features to remain disabled provided their capability is then reported as
undelivered — which is precisely the shape of this finding. But the audit's conditional framing —
"*if* live external scoring is enabled" — hides two parts that are unconditional today:

1. **The contradiction is already shipped in customer material.** `docs/kit/03-payload-schemas.md:147` is
   an M3 deliverable that documents `workers_ai` to the same customer whose §2.4 says no model runs on
   the decision path at any stage and whose commercial guide instructs the field to say "zero AI credits
   at any traffic volume" *verbatim*. Nobody has to enable anything for a privacy or legal reviewer to
   find that.
2. **The egress control is a safety gap, not a wording gap.** Any operator with a JWT — the write path
   is `PUT /content/learn`, `src/routes/content.ts:52`, fail-closed auth, no further gate — can point
   every shopper's behavioural profile and the entire content catalog at an arbitrary internet host over
   plaintext HTTP, from the shipped tuning UI, with no allow-list, no confirmation and no alert. On the
   brief's scale that reads as live-data safety, i.e. **blocks launch** the moment real shopper data flows
   — which is the pilot.

**Size: I agree, S + M, and would split it explicitly.** S (1–3 engineer-days) for the gate, the validator
restriction, the eligible/bounded candidate list and the missing test. M (1–2 engineer-weeks) for a real
offline score publication seam — and the audit is right that one is needed, because **the `table` kind has
no writer at all** (see §5).

## 4 · What the audit got wrong

1. **"availability dependencies" is overstated.** `fallback: 'omit'` is honoured
   (`external.ts:110`, `service.ts:215–219`): a dead model cannot fail a decision, it omits the term and
   the receipt says `status: 'unavailable'` with the reason. What an enabled hook actually adds is a
   **latency** dependency (up to `timeoutMs`, validator-capped at 5000 ms) and a **result-stability**
   dependency (the same shopper gets a different ranking depending on a third party's uptime, which
   quietly contaminates any lift measurement). Stating it as an availability risk gives a reader an easy
   rebuttal — "we have a fallback" — that is technically correct and misses the point.
2. **`external.ts:73` is cited for two mechanisms.** `:73` is the HTTP/`service` case; Workers AI is `:85`.
3. **"Repository v8 scope §2.4"** is not readable in the repository as a line. The verifiable citation is
   `docs/opticon/Scope-of-Services-v8-Change-Log.md:39–40` (and `docs/Tapestry-Nitin-Round-Two-Answers.md:155`).
   The SOS itself is a `.docx` that this audit did not open.
4. **"portions of the customer solution document" names the weaker document.** The sharp citation is the
   integration kit, `docs/kit/03-payload-schemas.md:147`, an M3 customer deliverable.
5. **"cancel cancellable work on deadline" is a partial remedy the audit does not qualify.** On Workers,
   `fetch` is cancellable only through an `AbortSignal`, which this code has none of — fixable. But
   `ai.run()` (`external.ts:87`) exposes no cancellation at all, so for the `workers_ai` kind an
   `AbortController` closes nothing and the credit is spent regardless. If the remedy is read as "add an
   AbortController and the credits question is answered", it is wrong.

## 5 · What the audit missed, adjacent to this finding

1. **The operator UI ships the control.** `public/learning.js:423–426` renders a subhead "Their model, for
   every slot" with a **Kind** dropdown containing `workers_ai`, a free-text **Ref** field placeheld
   `"MODEL, or https://…"`, and a **Budget** input with `max: 5000`; `:394` is the per-slot "Weight, w_ext"
   dial. This is not a developer-only config hook — it is two clicks and a URL in the tuning UI the
   customer's business team is explicitly promised control of ("weights live-tunable by your team",
   `Scope-of-Services-v8-Change-Log.md:31–32`). The audit's phrase "an enabled optional hook" undersells
   the reachability by a wide margin.
2. **No scheme or host validation, no allow-list.** `external.ts:75` `/^https?:\/\//` accepts plaintext
   `http://`; `kinds.ts:305` accepts any non-empty `ref`. Verified in R5. The audit's remedy says "data
   permissions" but never says the code has none.
3. **`timeoutMs` up to 5000 ms.** `kinds.ts:308` and the UI's `max: 5000` against a documented 20 ms budget
   (doc 22 §9) and a <200 ms P95 target (brief §6). A 5 s budget is 25× the target.
4. **No environment gate and no kill switch.** `src/types/env.ts` has `REFLEX_ENABLED` (:90) and
   `DEMO_EVENT_CAPTURE` (:74) as safety switches; there is no equivalent for the external model, and
   nothing keys off `ENVIRONMENT === 'production'`. A stored document is the only control.
5. **The `table` kind — the one kind with no model on the path — has no way to load it.** `extTableKey`
   (`external.ts:35`) is referenced in exactly two places, both reads inside `external.ts`. Nothing in
   `src/routes/` or anywhere else writes `ext:{tenant}:{brand}`: no PUT, no import, no validator, no
   revision, no rollback, no actor, no audit row. The kit and doc 22 §9 tell the customer's data science
   team to use `table`; the only way to supply one is an out-of-band KV write outside the versioned store.
   This is the finding's own remedy — "precomputed, versioned scores published through the same immutable
   activation process" — and the seam is absent rather than informal.
6. **The call fires with an empty candidate set.** `wantsExt` (`service.ts:197`) does not test
   `catalog.pieces.length`. Observed accidentally during harness bring-up: with an unloaded catalog the
   POST still went out, `candidates: []`. A tenant whose catalog document failed to write burns egress
   (and, on a stamp with an AI binding, credits) on every decision for nothing.
7. **No test asserts that "off" makes no model call.** `src/learn/phase3.test.ts:79–95` exercises
   `scoreExternal` with injected deps only. Nothing anywhere asserts that `serveContentDecisions` performs
   zero `fetch`/`ai.run` calls when `external` is absent. The audit's own remedy asks for exactly this
   validation, and it does not exist. R3 in my harness is that test and can be lifted verbatim.
8. **A test that passes for the wrong reason.** `phase3.test.ts:88–90` — `const slow = …setTimeout(…200)`,
   then `expect(late.ok).toBe(false)` and the reason matches `/timeout after 10ms/`. It proves the *caller*
   gave up at the budget and reads as proving the *call* was bounded. R4 shows the upstream work completes
   afterwards. The honest version adds an assertion that the slow call had not finished at the point of
   return and had finished later — which is exactly the fact that decides the credits question.
9. **Nothing alerts when the contract line goes false.** The five-minute self-monitor
   (`src/ops/monitor.ts:66–71`) drives a decision with `opt_personalization_enabled=false`, so it lands in
   the `default` arm and never exercises the external path. There is no check anywhere that a stamp's
   learn document has `external` set. The first person to learn that the "no model on the decision path"
   line stopped being true would be whoever next read the config by hand.
10. **`POST /v1/:tenant/models/reference`** (`src/routes/decisions.ts:452–464`) carries no JWT; it sits
    behind `sdkKey()` (`src/index.ts:86`), which is permissive in the default `AUTH_MODE: 'open'`. It is
    stateless and takes candidates from the caller, so it is a compute surface rather than a data leak —
    worth a rate limit, not a finding.

## 7 · Assessment of the remedy

The audit's remedy has four clauses. My reading of each:

| Clause | Assessment |
|---|---|
| "keep customer render paths on precomputed, versioned scores published through the same immutable activation process" | **Right, and under-specified.** This is the `table` kind, and it has no publication path at all (§5.5). Say so, or the team will think it is a policy change rather than a build. |
| "Alternatively explicitly amend the optional-mode contract, data permissions, economics, and SLOs before enabling live scoring" | **Right and necessary**, but it is the *slower* branch. It requires reopening a signed §2.4 and a pricing promise the field is told to use verbatim. Do not present it as the equal-cost alternative. |
| "Send only eligible bounded candidates and cancel cancellable work on deadline" | **Right on candidates** (a one-line filter plus a cap; see R8 for why it is not cosmetic). **Partly wrong on cancellation** — no cancellation exists for `ai.run` (§4.5). |
| "Keep the deterministic scorer as the mandatory fallback; validate that 'off' truly performs no model calls or model-credit consumption" | **Exactly right, and currently unmet** — the validation does not exist (§5.7). |

**Over-scoped:** nothing. **Under-scoped:** the remedy does not mention the operator UI that exposes the
control, the absent `ref` allow-list, the 5000 ms budget, or the missing kill switch — all of which are
cheaper than the publication seam and all of which are what actually stands between "off by default" and
"off by design".

### Smallest safe fix that closes the launch-blocking part

Four changes, roughly one engineer-day, none of which touch the decision arithmetic:

1. **`src/content/service.ts:197`** — gate the hook on the environment, not only on the document:
   `const wantsExt = extCfg !== null && env.EXTERNAL_MODEL_ENABLED === 'true' && arm !== 'default' && …`,
   with `EXTERNAL_MODEL_ENABLED?: string` added to `src/types/env.ts` and unset on every stamp. A stored
   document can then never re-enable live scoring, whatever an operator clicks.
2. **`src/content/kinds.ts:305–310`** — restrict what validates by default: accept `kind: 'table'`, and
   `kind: 'service'` only when `ref` is a **binding name** (no `http(s)://`); reject `workers_ai` and URL
   refs unless the same environment switch is on; clamp `timeoutMs` to ≤ 50. Existing stored documents
   fail validation loudly on next write rather than silently keeping a URL.
3. **`src/content/service.ts:201`** — send `catalog.pieces.filter((p) => isEligibleAt(p, now))` and cap the
   list (import already available from `@/content/lifecycle`). Stops embargoed content leaving and takes
   the body from R8's numbers to the eligible subset.
4. **A test in `src/learn/phase3.test.ts`** asserting `serveContentDecisions` performs zero `fetch` and
   zero `ai.run` calls with `external` absent, with weights at zero, and with the gate off — my R3 lifts
   straight in — plus the missing cancellation assertion on the existing timeout test (§5.8).

Then, before the kit ships at M3: **correct `docs/kit/03-payload-schemas.md:147`** to list only what the
gate permits, and add one sentence to doc 22 §9 saying live model kinds are off by deployment and require
a contract amendment. That is the half that stops the customer reading two of our documents and finding
they disagree.

The `table` publication seam — a `PUT` for `ext:{tenant}:{brand}` through `src/config/versionedStore` with
revisions, actor, note and rollback, matching every other document kind — is the M, and it is the thing
that makes the North Star true rather than merely enforced.
