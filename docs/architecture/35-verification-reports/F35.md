### 2.1 The documented deploy runbook, executed once, on a fresh database

`docs/deployment/01-deploy.md:70-75` is the canonical Database step:

```bash
npx wrangler d1 migrations apply coach-demo-db --remote
for f in migrations/seed/seed_*.sql; do npx wrangler d1 execute coach-demo-db --remote --file "$f"; done
```

Migrations sort `0001…0010`, so `0008_meridian_geo_cohort.sql` runs first. The glob sorts
`seed_001 … seed_010, seed_011_geo`, so `seed_011_geo.sql` runs **last**. I ran exactly that order:

ZIPs destroyed and never restored: `10003, 10011, 10012, 10013, 10014, 10016, 10021, 10023, 10024, 11201,
11215, 11217, 11231`.

**This is not a "re-run" hazard. The first documented run already lands in the degraded state.**

### 2.2 Why it fails silently

`src/demos/meridian/geoCohort.ts:58` sets `MIN_COHORT_SHOPPERS = 30`, and `:527` clears a rung when
`sampleSize >= MIN_COHORT_SHOPPERS`. Post-runbook the metro rung has **44** distinct shoppers — still above
30. The ladder **clears** and the stage presents a "New York metro" cohort computed from 44 shoppers in a
single ZIP, labelled as the metro, with no warning anywhere. A visitor in one of the 13 deleted ZIPs gets
`metroCbsa = null` at `:295-305` ("crosswalk missing or unreadable → the ladder simply has no metro rung")
and skips the metro grain entirely.

The provenance regression is the part nobody has written down: `docs/architecture/13` and the Opticon
coverage doc make "census REAL public, cited per row" a stage claim. After the runbook, the NY-metro row
the demo reads says `Representative (... proxy)`. The claim on stage becomes false, and the only signal is
inside a database column.

### 2.3 Recovery

Re-executing `0008` manually restores everything (`:92` narrowly deletes the proxy row, `:93-94` reinserts
the real one, `:99` `INSERT OR IGNORE` restores all 14 ZIPs). Verified: after re-exec, NY ZIPs back to 14,
`35620` back to 99,852 / `Census ACS 2024 1-yr`, cohort back to 640. But **`wrangler d1 migrations apply`
will not do it** — 0008 is already recorded applied. Recovery requires someone to know to run
`wrangler d1 execute --file=migrations/0008_meridian_geo_cohort.sql`, which no document says.

### 2.4 The proposed minimal fix, proven

Seven lines. Re-ran the full runbook order with the fixed seed:

## 6 · Severity, size, remedy

**Severity: fix before the next customer** (audit said: improvement). The litter and the README are
improvements and I would not argue otherwise. But the geo seed is the minimum portability gate in the
brief's own words: the handoff artefact is a runbook that instructs an engineer to run an unscoped
`DELETE FROM geo_census; DELETE FROM geo_xref;` against a remote database, and doing so degrades a
CEO-facing demo silently while falsifying a stated data-provenance claim. It does not block the January
Tapestry launch — the Tapestry decision engine does not read these tables — so "blocks launch" would be
inflation.

**Size: S for the evidence items, M for the stated remedy.** The audit's "S–M" is right for the artefacts
and wrong for its own remedy paragraph: "verified fresh-clone setup", "generated command/API documentation"
and "tenant-safe seed fixtures" are each independently M. The remedy is over-scoped relative to the size it
claims.

**Smallest safe fix that closes the part with real blast radius — roughly half a day:**

1. `migrations/seed/seed_011_geo.sql` — delete `:32-33`; make the five geo inserts at `:41, :58, :114, :138,
   :156` `INSERT OR IGNORE`. Proven in §2.4.
2. `docs/deployment/01-deploy.md:70-75` — mark the seed loop first-time-only, or exclude `seed_011_geo.sql`
   from the `--remote` loop, and name `wrangler d1 execute --file=migrations/0008_meridian_geo_cohort.sql`
   as the recovery step.
3. Add one regression test that applies `0004 → 0008 → seed_011` and asserts 14 NY ZIPs and
   `source = 'Census ACS 2024 1-yr'` for `35620`. My harness is the test.
4. `chmod -x`/delete or clearly quarantine `scripts/setup.sh`, or fix its wrangler-4 syntax and add an
   account guard. It is the one tracked file that can mutate someone else's Cloudflare account today.

Everything else in F35 — 103 tracked files, 3.30 MB, three README copies, the JWT placeholder, the missing
`.dev.vars.example`/`DEMOS.md`/`VERIFICATION-HARNESS.md` — is real, is S, and is correctly labelled
improvement. It should ride a single reviewed cleanup commit, not gate anything.
