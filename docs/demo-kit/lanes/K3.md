# Lane K3 (part a): the demo kit's script libraries

**Opened 2026-10-01 by the lead.** Design: [Demo-Kit-Design.md](../Demo-Kit-Design.md) §2.3 and §4. The sources to generalise are Vantage's scripts; the framework lane's map cites their line ranges: [lg-framework-map.md](../../lg/research/lg-framework-map.md) §1.

## Scope, part a (now)

Create the libraries and the config-driven CLIs, proven equivalent to Vantage's scripts, **without modifying Vantage's scripts**. Lane C1 is editing the two rehearsal scripts and runs `seed-vantage.mjs` while it works, so the swap of Vantage's scripts to thin wrappers is part b, after C1 lands.

1. `scripts/demo-kit/lib/seed.mjs`: windows re-anchored to now, beat envelopes, the bootstrap publish, the local checks, lifted from `scripts/seed-vantage.mjs`.
2. `scripts/demo-kit/lib/region.mjs`: the all-states synthetic regional seed from a vocabulary, lifted from `scripts/seed-vantage-region.mjs`.
3. `scripts/demo-kit/lib/imagery.mjs`: fetch by URL list, resize and encode, a manifest with provenance per file, lifted from `scripts/fetch-vantage-devices.mjs` (and the art generator only if it shares code worth lifting; otherwise leave it).
4. CLIs: `scripts/demo-kit/seed.mjs`, `region-seed.mjs`, `fetch-imagery.mjs`, each taking `--config <file>` plus `--base` and `--token` as today, where the config is a JSON file describing the demo's documents, beats, vocabulary and imagery sources. Write `scripts/demo-kit/configs/vantage.json` as the first instance, pointing at Vantage's existing files; it is the start of `demo.config.json` in the design, not the whole of it.
5. `scripts/demo-kit/check-demo.mjs <config>`: runs `npm run check:generated`, the app typecheck, a credential grep over the demo's `public/` directory (tokens, JWTs, secrets by the patterns the repository already uses in its checks; read `docs/demos/BOOTSTRAP.md`), and both suites against `--base`.
6. Tests with `node:test`, as `scripts/build-demo-worker-config.test.mjs` does: envelope shape, window re-anchoring, the per-state unit counts of the region seed, the manifest shape, the config validation.

## Proof of equivalence

Run a local Vantage **on your own port and state directory**: `npx wrangler dev --config wrangler.vantage.toml --port 9112 --persist-to .wrangler/state-k3`. Seed it once with `scripts/seed-vantage.mjs --base http://127.0.0.1:9112 …` and capture the published documents; reset; seed it with `scripts/demo-kit/seed.mjs --config scripts/demo-kit/configs/vantage.json --base http://127.0.0.1:9112 …` and capture again; the documents must be equal apart from the re-anchored timestamps, and you report the diff. The region seed likewise: the same units per state per dimension. The imagery library: re-fetch two of Vantage's devices into a temporary directory under the scratchpad and show the manifest entries match the shape of `public/vantage/img/MANIFEST.json`. Do not write into `public/vantage/`.

### Proofs

The local Vantage was mine alone: `npx wrangler dev --config wrangler.vantage.toml --port 9112 --persist-to .wrangler/state-k3 --inspector-port 9242`, under WSL (only WSL has `workerd`), with D1 migrations and the census rows as the resume describes. Run 1's state is kept as `.wrangler/state-k3-run1`; the final state is `.wrangler/state-k3`. The server is stopped. 9110 and 9111 were never touched.

**The reference never wrote `public/vantage/`.** `scripts/seed-vantage.mjs` ran unmodified, with a preload (scratchpad only) that redirects every write under `public/` into the scratchpad and refuses any other write into the checkout. Before its first run I hashed the 19 files it writes (`catalog.json` and the 18 under `beats/`), and copied them into the scratchpad when the coordinator's addition arrived. After every run, and at the end, **all 19 match that snapshot by hash, so no restore was ever needed**; `img/` is unchanged too. The four page files that did change during my runs (`index.html`, `phone.html`, `vantage.css`, `vantage.js`, from 18:01) and `scripts/rehearse-vantage-dom.mjs` are Lane C1's edits; `src/demos/README.md` is not mine either.

1. **The seed: published documents.** A is `seed-vantage.mjs` on a fresh state. B is `demo-kit/seed.mjs` after `POST /vantage/api/reset`. C is `demo-kit/seed.mjs` on a second fresh state.
   ```text
   A vs C (both fresh, both at revision 2)
   reflex  A rev 2 · B rev 2; document equal; effective equal; note equal
   catalog A rev 2 · B rev 2; document equal (64 instants, each relative to its anchor); note equal
   slots   A rev 2 · B rev 2; document equal; note equal
   learn   A rev 2 · B rev 2; document equal; note equal
   ✓ equal, apart from each seed's own anchor
   ```
   A against B is the same four "equal". The only difference is the server's revision label on `version` (`content-vantage-open+r2` against `+r4`), which the server writes on every stored document so that two revisions never share a label (`src/content/kinds.ts`, `src/reflex/configStore.ts`). The reset itself was confirmed in between: capture R shows `open-catalog` and `open-slots` at revision 3, so B was the kit's own publish.
2. **The seed: wire and files.** Against a recording stub, with no server and no secret, all 9 requests are identical, serialisation and key order included: the bootstrap carrying the four documents, then the GET and PUT pairs. Only the instants (relative to each anchor) and the random idempotency suffix differ. The kit exercised both bootstrap paths (`created`, `already_initialized`). The 18 beat files each seed writes are byte-identical once each instant is written relative to its anchor: 195 instants, every one moved by exactly the anchor difference (664,402 ms). The reference's regenerated `catalog.json` is byte-identical to the committed one, so the kit leaves it alone: it carries no instant.
3. **The region seed: the same units per state per dimension.**
   - Offline, `seed-vantage-region.mjs --dry-run --rows` and `demo-kit/region-seed.mjs --dry-run --rows` print the same 104 lines. That is every row of all 51 regions, 21,675 units.
   - On the server, 51 of 51 regions answer at region level for both scripts. Seeded units, events, level, label and leaders are equal in every region in every run (A, B, C).
   - Shares are equal in 48 of 51 regions (A against B) and in 50 of 51 (A against C).
   - The cells that differ are boundary ratios: 150/160, 25/400, 105/240 and 15/240 are exact half-thousandths, and 52/179 is within 3×10⁻⁶ of one. The region object rounds each decayed R to three decimals at publish, so these cells flip with the ingest's milliseconds in either script. The reference flips against itself (rerun A3: `US-NY brand.samsung` 0.438, then 0.437), and a kit rerun (B3) matches A in all five cells.
4. **The imagery library.** `iphone-18-pro` (a pair) and `pixel-11` (a back-and-front compose) were fetched again from the makers' CDNs, three source images and 3.5 MB, into the scratchpad under WSL. The results:

   - The manifest rows equal the committed rows in shape (keys, order, value types) and in every value except `sources[].retrieved` (2026-10-01 against 2026-09-30).
