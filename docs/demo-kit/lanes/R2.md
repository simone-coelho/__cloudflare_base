  - The routes are absent off the demo profile: 404, with nothing read.
  - The beat list is closed, copied and frozen, and prototype names are refused.
  - Each action mints a 60-second operator token.
  - A receipt id is checked for the tenant prefix and the subject before any read, and the record's owner is checked after it.

- **Note 1, the `ctx.` prefix stripped with `/^ctx./`: nothing to fix now.** The pattern accepts any one character after `ctx` (`ctx-intent`, `ctxXintent`), but the value is still checked against the closed intent set or the region-key pattern, and the result only goes back to the page, labelled `from: 'request'`. Escape the dot when the file is next touched: with `/^ctx\./` all 63 tests still pass (K1-i).
- **Note 2, `/receipt` does not compare X-Tenant with the demo's tenant: a hardening. Do it before any worker serves two kit demos.** I tested it with a scratch probe:
  - On a single-tenant worker, a capability for another tenant cannot be presented at all (401, nothing read).
  - On a worker that provisions `kestrel` and `vantage`, a `kestrel` capability sent with X-Tenant `kestrel` reads `/v1/vantage/ledger/<id>` and gets a 200.
  - Only a record whose `visitor_id` equals the caller's own subject can be reached, and anonymous subjects are minted at random for each tenant. So no other person's record is exposed: the gap is in tenant binding, not privacy.
  - The fix is to answer 404 in the receipt route when `principal.tenant !== tenant`. With it, all 63 tests stay green (K1-j).
- Low: no kit test returns another visitor's record, so only `src/routes/vantage.test.ts` guards the owner check after the read (K1-f). That is fine while both run in one command, as they do.
