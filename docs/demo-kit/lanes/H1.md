### What changed

1. **`/receipt` is bound to the demo's tenant** (`src/demos/kit/actionRoutes.ts`). The first thing the route does after `requireShopper` is answer `404 { ok: false, error: 'not found' }` when `principal.tenant !== tenant`. That happens before the body, the ids or any dispatch, so the route is absent to another demo's shopper, not just refusing her. The header comment says so too.
   - Tests (`actionRoutes.test.ts`, new describe block) run on a worker that provisions both `kestrel` and `vantage`, with a ledger that answers any tenant's id as hers (R2's probe):
     - The control: each demo's own shopper gets 200 from its own ledger.
     - The other demo's shopper gets 404 with nothing read, in both directions, whatever she sends: an id on this demo's prefix that names her (R2's case), several of them, one on her own prefix, or an empty body.
     - Her capability sent with the demo's X-Tenant gets 401 from `requireShopper`, with nothing read.
2. **The credential grep covers everything the pages load** (`lib/credentials.mjs`, `check-demo.mjs`).
   - How the scan set is built. The config has no `pages` field, so `servedPaths({ root, publicDir })` starts from the config's `publicDir` and the kit's `public/demo-kit`. It then reads every html, js, mjs, css, json and svg file there for the paths they name: quoted, backtick, `url(` or `=` references, root-absolute or relative, never `//` or external.
     - Each path is mapped to the top-level directory or file under `public/` it lands in, and the walk repeats until nothing new is named.
     - Names that land outside `public/`, or on nothing that exists (API routes such as `/v1/…` and `/realtime/…`), are skipped.
   - For Vantage today the set is `public/vantage`, `public/demo-kit`, and `public/html2canvas.min.js` (named by `compare.js`).
   - `scanForCredentials` now takes `dirs`, where each entry is a directory or a single file. `dir` still works for the existing callers.
   - `check-demo` lists every scanned path with the file that named it, and puts the list in its detail line.
3. **Validator lows** (`lib/config.mjs`):
   - **Workers and queues.** `worker.name` refuses `edge-platform-staging` and `edge-platform-production`, besides `edge-platform`. `worker.queue` refuses the customer stamps' queues (`events-staging`, `events-production` and their dead-letter queues) as well as the shared ones. The queues go slightly past the brief's wording; they come from the same stamps in `wrangler.toml`.
   - **`worker.config`.** It refuses any path that resolves to the root `wrangler.toml`: `./wrangler.toml`, `scripts/../wrangler.toml`, and `WRANGLER.TOML`, compared without regard to case.
   - **`publicDir`.** It must be `public/<slug>`; a trailing slash is still accepted. The existence check still runs, so the two existing publicDir assertions pass unmodified.
   - **Credential keys** are matched by pattern (`isCredentialKey`, exported):
     - Refused: any key containing token, secret, password or passwd, jwt, bearer, authorization or credential, in any case; any key whose last word is `key` or `keys` (apiKey, private_key, SIGNING-KEY, sdkKey); and the common compounds run together (apikey, privatekey, …).
     - Not matched: a bare `key`, because the Vantage imagery section holds `placeholder.key` and a source's chroma `key`, and `keyTol` only leads with it. Only string values are refused, so lists of secret names and design-token objects stay fine.
4. **The `ctx.` prefix** in `src/demos/kit/helpers.ts` is now `/^ctx\./`. The test checks that `ctx.intent` and `ctx.region` are still stripped, and that `ctx-intent`, `ctxXintent`, `ctx_region`, `ctx/region`, `ctx..intent` and `CTX.intent` are each refused by name.

### Not done, and why

- **The request-level suite's committed-file list still omits `public/demo-kit`.** That was R2's other half of finding 1. `scripts/rehearse-vantage-*.mjs` are suites this lane may not touch; that half is for C2 or K3c.
- **Other demos' workers (`edge-platform-top-offers`, `edge-platform-vantage` under another slug) are not refused.** R2 listed them, but the brief names only the customer stamps. Binding `worker.name` to the slug (for example `edge-platform-<slug>`) would close this; it is a ruling for the lead, not something I assumed.
- **A known trade-off of the key pattern.** A data key that merely contains a credential word and holds a string is refused as a credential. Example: a beat named `07-secret-sale` in `seed.beats.publishable`. The refusal names the key, and renaming the beat clears it. I chose the conservative side because header-style keys such as `x-api-key` are real credential carriers.
- **The served set comes from the pages' text, not from a `pages` field.** The config has no such field yet (design §2.4). A path assembled at run time from pieces that never appear as a literal would not be followed. `public/demo-kit` is always a starting point regardless.
