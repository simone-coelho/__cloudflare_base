# Lane K6: a demo worker's root is its demo

**Opened 2026-10-02 by the lead** (decisions log, last row): every demo worker's `/` served the repository's legacy dashboard (`public/index.html`, a WebSocket status page that reads "Disconnected"), while the demo lives at `/vantage/`, `/oh/` or `/top-offers/`. **Round 2, the same day:** the coordinator ruled on the hand-back, extended the grant, and had the lane apply the rulings itself. Both rounds are below. Nothing is committed.

## Report

### What the worker does now

Under `DEPLOYMENT_PROFILE=demo`, a worker that provisions exactly one tenant, and that tenant a demo's:

| Request | Answer |
|---|---|
| GET or HEAD `/` | 302 to the demo's root (`/vantage/`, `/oh/`, `/top-offers/`), query kept, `Cache-Control: no-store` |
| A GET or HEAD **navigation** (a browser loading a page) to a path that is not an API path | The same 302. A visitor never sees "Tenant unavailable" or the dashboard |
| An API path: anything under what `src/index.ts` mounts (`/v1`, `/realtime`, `/sort`, `/<slug>/api`, `/api-info` and every other mount), plus the Agents SDK's `/agents` | Its own answer, exactly as before, navigation or not |
| A script's fetch of a missing file (not a navigation) | Its own 4xx, as before |
| The demo's own root reaching the worker (only if its file were missing) | Not redirected, so it cannot loop |

A demo worker that provisions several tenants, or one that is no demo's, serves `/` as before (the same file, through `env.ASSETS`), and every other path as before. The customer profile is untouched.

**The API paths are derived, never typed.** They come from the app's own route table, `app.routes`. Hono records `basePath` on every route a sub-app mounts, so `app.route('/vantage/api', …)` yields `/vantage/api`. A route on the app itself contributes its static part, so `app.get('/api-info')` yields `/api-info`. App-level middleware (`app.use('*' | '/x/*')`) is not a mount, and `/` is never a prefix. The only typed prefix is `/agents`: `routeAgentRequest` answers it before the app, so the table cannot hold it. The worker-entry test reads every `app.route(...)`/`app.get(...)` path from the source of `src/index.ts` and checks that each one, and a child of each, gets the same answer as a navigation as it does as a fetch.

**One departure from the letter of ruling 2, for the coordinator to confirm.** The unknown-page redirect applies to navigations only, not to every GET or HEAD. A navigation is `Sec-Fetch-Mode: navigate`, or, when a client sends no fetch metadata, `Accept: text/html`. I made this change after checking what a redirect on every GET would break:
- The "must not be served" checks in the Vantage, OH and Top Offers request suites fetch `beats/operator.local.json` and expect anything but 200. A 302 to the demo page, followed, is a 200. Those credential checks would fail, and they would also stop meaning anything.
- A script fetching a missing JSON file would receive an HTML page in place of a refusal.

`/` still redirects for every GET or HEAD.

### The asset settings (ruling 1)

`scripts/build-demo-worker-config.mjs` now writes `run_worker_first = ["/"]` and `not_found_handling = "none"` into every demo worker config. The builder's test is extended: 7 tests, up from 6. `wrangler.vantage.toml`, `wrangler.oh.toml` and `wrangler.top-offers.toml` were regenerated by the builder itself, so the preflight's byte-equal check holds. Each differs from the committed file by the same two lines, and each equals the patch-1 build. Both settings are needed. Once `run_worker_first` is a list, the asset layer applies `not_found_handling` to every request it routes itself (miniflare `assets.worker.js` `canFetch`: `has_static_routing`). With `single-page-application` still in place, every API GET came back as `index.html`. With `none`, an unmatched request reaches the worker.

**A side effect for the other lanes.** `wrangler dev` watches its config, so the OH rigs other lanes were running on `wrangler.oh.toml` picked up the new settings when the file changed. On a rig that provisions oh alone, `/` and unknown pages now redirect. The request suites' "must not be served" checks still pass, because those requests are not navigations.

### Round 1, for the record

The first hand-back found that the code line alone changes nothing on a deployed demo worker. The asset layer serves `public/index.html` for `/` before any code runs, and the lane proved this on the committed config. It also found that `run_worker_first = ["/"]` without `not_found_handling = "none"` turns every API GET into `index.html`. Round-1 counts, on patched copies of the configs:
- Vantage: request level 115/115 and 116/116 with the root check; DOM 298/298; 115/116 on six tenants, the root check alone failing.
- OH (`.wrangler/state-k6`, its own `public/` copy, `public/oh/beats/` never written): request level 217/217 on fresh restarts with and without the change; DOM 455/456, the one failure (a dryer card naming the wrong `/sort` driver) also failing on the control rig.
- `src/index.api-boundary.test.ts`: the first cut added 8 failures by reading `DEPLOYMENT_PROFILE` before the path; fixed then, and the order is kept now.
