# W01.01 proposed boundary and negative-test contract

This is a proposal under [plan-v1](plan-v1.md), grounded in the [current inventory](inventory.md) and [source manifest](source-route-manifest.json). No rule below is implemented or newly authorized for implementation. Current route gates are described separately in the inventory. D01 and D08 remain pending. The task can deliver a reviewed design while full W01/F01/F03/F25/F33/N01/N03/G0 remains open.

## Proposed invariants and decision ownership

A customer deployment needs an explicit path + method + upgrade + capability policy **before dispatch**, including the pre-Hono Agent router, nested subrouter fetches and assets. Default is no capability on the customer stamp unless admitted. A retained prefix never authorizes every method or child route. Route denial occurs before a customer store read, seed/session write, DO lookup, queued work, telemetry payload or external request. Authentication-policy reads and a separately specified, sanitized security audit are the only proposed exceptions; they must be enumerated and reviewed, never treated as an unlimited “logging” allowance.

Resolve one canonical customer/brand/environment context and require every path/header/host/query scope/body brand/credential selector to agree or map through an explicitly authorized mapping. The result must be passed to each handler, subrouter, store, connector, job and socket. Reject unknown/unprovisioned/ambiguous tenants instead of silently entering the default namespace. A site key identifies a site's access to the shopper API; it is not operator authority, account-link proof or ownership of an arbitrary visitor/session. A Bearer credential must carry accepted role, membership and account/session policy. Header/query precedence and conflicting credentials must be explicit; today a nonempty invalid SDK key blocks the Bearer fallback.

GET/HEAD/OPTIONS are separate method decisions. Proposed HEAD handling for effectful GET endpoints must not silently collect a decision, open a shopper, seed data or spend external quota. Either omit HEAD with an explicit non-mutating denial or implement a specific authorized metadata response. Pure authenticated reads can retain HEAD with identical access rules. OPTIONS may answer a known retained method/origin/header combination without shopper identity, but must be side-effect-free and cannot advertise prohibited capabilities. CORS alone never authorizes the actual request.

D01 has two candidate delivery mechanisms: separate customer/demo deployables with separate relevant resources; or a customer artifact that omits/explicitly disables prohibited routes, Agent discovery, assets, resources and background paths. Both require measured proof; neither is selected here. D08 must identify customer/brand/environment/resource ownership and applicable regional obligations while preserving the recorded per-customer stamp intent. No agent vote supplies leadership/security/customer approval. Exact existing live deployment/resource contents remain unverified.

## Proposed negative-test harness and observation contract

Use the **actual default export fetch** plus the actual mount graph, not a miniature replacement Hono app. Source extraction checks route-set drift but cannot exercise behavior. A later authorized runtime harness must run the real compiled artifact with entirely synthetic credentials/data, both REFLEX_HOST=session/do, customer capability profile and named base/staging/production config fixtures. Test AUTH_MODE=enforced, omitted/unknown values, and explicit demo/open configuration isolated from the customer profile; customer deny policy must not accidentally disappear if AUTH_MODE is misspelled. Include a no-credential baseline and an allowed control in each relevant fixture.

Fixture tenants `brand-a` and `brand-b` are both non-default and use different SDK keys, operator/service memberships, account identities, sessions, document sentinels and destination namespaces. Include a third foreign/unprovisioned brand; hostA/hostB/shared host/unknown host; X-Tenant absent/A/B/unknown/malformed; path A/B; scope A/B/default/malformed; query/body brand A/B; wildcard site key; no key/invalid key/valid key; missing, malformed, expired, refresh-type, revoked, wrong-role and wrong-membership Bearer; valid Bearer with absent versus invalid supplied SDK key. Source selectors such as surface must not change authorized tenant.

Instrumentation must record safe operation metadata at **all** destinations: CACHE/SESSIONS get/list/put/delete including TTL and logical/physical keys; STORAGE head/get/list/put/delete/content hashes; D1 prepare/bind/read/write table scopes; DO idFromName/get/fetch, state/alarm/socket calls and frame traffic; EVENT_QUEUE send/sendBatch and scheduled/retried work; AE point count/schema; global fetch/Fetcher/AI/BROWSER/ASSETS; isolate memory/memo/queued work; Set-Cookie; request/error/queue logs. Denied reads must not disclose sentinel bytes or open a private reader just because no write occurred. Snapshot each synthetic destination before and after; await waitUntil, drain in-scope queues/alarms/visitor chains, and inspect a subsequent authorized read and socket state. Required asynchronous work cannot be ignored because the response already returned.

For a prohibited route the oracle is **zero dispatcher/handler/namespace/destination access**, aside from an explicitly approved minimal edge audit that has no raw URL query/body/credential/subject fields. For a retained route denied on credentials/role/context, permit only the exact credential/membership read and sanitized audit needed by the accepted authentication interface; all business-data reads/writes/egress and subject allocation remain zero. Label those permitted policy operations in spies so a broad “some DB reads are fine” assertion cannot pass. Compare state, attempts and disclosed output as well as status; expected 401/403/404/405 alone never proves containment.

These cases are **not run** in W01.01. Future acceptance must record separate per-case actual results, artifact/configuration hashes and limitations; no skip/N/A turns a missing required case into a pass.

## Evidence and acceptance layers

W01 containment acceptance requires a frozen implementation artifact, policy/configuration/resource manifest and independently executed NT01–NT25 cases applicable to the chosen operating boundary, with omitted capabilities demonstrably unreachable and retained capabilities using accepted authority interfaces. A case may be split into future atomic tasks, but no required branch disappears by marking the current inventory complete. NT26 and relevant W03/W08/W37/customer tests prevent “deny everything” from masquerading as delivered capability.

A Node helper or mocked dependency test is source/local evidence only. Real workerd tests are needed for Hono mount semantics, DO instantiation/storage/alarms, WebSocket upgrade/frame behavior and supported queue/storage APIs. Asset/SPA/host tests need the actual asset router. Cross-isolate/restart/failure tests need appropriate runtime isolation. Account-side route/resource/secret ownership needs separately authorized deployment attestation without recording secret values. Browser/SDK/SFCC/feed/SSO/ODP/warehouse and customer acceptance remain their own evidence classes. No SLO, physical retention, residency, six-month reporting or incremental-lift conclusion comes from this task.

The twelve customer clauses, document-20 dispositions and D1–D13 in doc35 §4 remain authoritative; D01–D10 here refer to §7 human decisions. Primary boundary coverage is §1.7; retained profiling/audience/tuning/sort/history/export surfaces preserve §1.1/§1.2/§1.4/§1.6/§1.8/§1.11/§1.12. Generic enrichment/search/entitlement/warehouse (§1.3/§1.9/§1.10/§1.12) cannot be silently dropped by a demo prohibition. Conditional §2.3 widgets/templates remain optional no-cost handoff as available, not an invented January build. W14/W40/W41 acceptance stays separate.

Rework before acceptance is recorded honestly; after acceptance use superseding records and revalidation. Exact next step after worker freeze is independent review, followed by lead disposition. All W packages, findings and gates remain open.
