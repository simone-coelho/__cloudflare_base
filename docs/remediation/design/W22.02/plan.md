## Acceptance and implementation

1. Strict raw-day and hourly reads throw ReportUnavailableError when a selected listed object cannot be read; malformed hourly JSON throws ReportInputError. Refuse before canonical report/hour or any shard put, even if earlier input was valid. Ordinary unlisted/empty hours remain valid; blank-line semantics unchanged. General non-strict loadDay retains legacy missing/malformed skipping and explicit truncation.
2. Hourly listKeys (including catchUp aggregate inventory) rejects missing/repeated continuation cursors while truncated and charges page/key visits against existing REPORT_LIMITS.work. Preserve valid pagination, sorting, product-sort exclusion and physical cap/truncated accounting; no new service or lower object cap.
3. Grouped raw case: missing decision and outcome after valid input, error class, unchanged canonical bytes/zero puts, restored source succeeds with full counts; legacy non-strict skip remains. Grouped hourly case: direct fold and same single-hour catchUp refuse missing/malformed input and bad raw/inventory cursors with no mutations; input restored permits one full-count/credit build, next catchUp no-op. Preserve pre-existing shard/report bytes, not only missing aggregate. Include valid paginated success and existing work guard if a lightweight synthetic case suffices. Do not pretend input repairs itself.
4. No scoring, attribution, identity, schema/basis, cap/horizon, erasure or publication-overlay changes. Reuse accepted W22.01 same-byte dependency/static baseline assurance; retain prior acceptance/history while qualifying its overlapping artifact. Concise API refusal/retry caveat only. Recovery proof is a single pending hour before later progress: catchUp still continues after failures, so later hours can advance/evict carry-in and are not rebuilt when an earlier input recovers; ringsFolded/historical incompleteness must not be represented as complete recovery.
