## 2. The contracts

**Item 1: complements.**
- Piece `complements: ["WM4000HBA", …]` and slot `complements: { weight: 0.3 }`.
- The anchor is `ctx.anchor=<product id>` on the snapshot. That is the signal the request contract already carries; the snapshot has no viewed-product member.
- A ranked piece whose `complements` lists the anchor exactly gains `weight` in its base score, before merchandising and the lift. It carries `{ dim: 'completes', value: <anchor>, a: 1, weight }`, and its receipt says *"Completes what she committed to: WM4000HBA (+0.3)."*
- It fails closed in each of these cases: no anchor, an empty anchor, an anchor that no piece completes, weight 0, a slot without the rule, the default arm, and a pin.
- Eligibility is unchanged. A page that gated companions on an anchor family in `ctx.anchor` (the interim pattern) moves the family to another signal (for example `ctx.category`) or lists the ids, because `ctx.anchor` now names the product.

**Item 2: named outcomes.**
- The page sends `{ type: 'custom', data: { event: 'partner_pickup' | 'retailer_referral', decisionId, contentId, slot, … } }`. The action type list is closed, so `custom` with the name in `data.event` is the wire form.
- The outcome record is `type: 'custom'` with `event` set to its own name. It is attributed under the learning policy's `custom` window (30 minutes by default, the same as a click), and exactly to the decision it names.
- A slot learns from it only where it publishes `reward: 'custom'`. The test shows this matches what a click slot learns from the same presses sent as clicks.
- The day report carries `namedOutcomes: { version: 1, basis: 'learning_policy', events: { partner_pickup: { outcomes, credited, bySlot: { <slot>: { <item>: n } } }, … } }`. It sits beside `visitorOutcomes`, where the orders are the `purchase` type, and beside the grids (the attach). It is never inside either, and it carries no value or revenue.
- The raw-day branch and the folded hours produce the same count, including across an hour boundary. `null` means an hour that cannot say; an absent member means a report built before the member existed.

**Item 3: the regional prior on `/sort`.**
- It applies only where `learn.regional.enabled` is true and `dimensions` is published. Without the list, a grid sorts exactly as before; the slots read an absent list as "every dimension", and a grid should not start leaning for tenants that never asked.
- The edge region (`cf`, carried through the owner forwarding as coarse country and region) leads. On the demo profile, a body `context.region` asserts one and the answer says `asserted: true`.
- At affinity 0 the platform's order comes back exactly, and the answer still names the prior.
- The product-sort record holds the same per-item drivers and stays valid under its strict schema.

**Item 4: Google's auto-tagged click.**
- These read `paid_search`: `classifyEntryChannel({ gclid, referrer: 'https://www.google.com/' })`, the same with no referrer, and the same with a referrer that is not a search engine.
- `entrySourceOf` gives `www.google.com`, `null` and `null` for those three cases.
- A declared `utm_source` is judged by the existing rules.
- An empty click id, or one longer than 512 characters, changes nothing.

## 4. Does item 4 touch W16's entry contract?

**Yes.** For a request to carry `gclid` to the classifier, `ChannelSignals` and `validEntry` (`src/services/visit.ts:39-57`, `:112-118`) would need to accept the key. So would `snapshotEntry`, the realtime action door and the SDK's UTM reader (`src/sdk/identity.ts`). That is the W16 C2 entry contract.

As the brief directs, the change stays inside the classification and its test:
- the classifier takes `ChannelSignals & AutoTagSignals`;
- `validEntry` still refuses `gclid`, which the test asserts;
- so no request reaches the new rule until the contract is widened.

Until that ruling, the OH page asserts the channel through the snapshot's existing `channel` parameter, a bounded fallback used only while owned state has no entry, and says so on the receipt (OH design §6.4).
