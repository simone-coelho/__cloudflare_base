# Re: real-time affinity/scoring — layer vs. vertical vs. trained model

All three — but they're not competing options. They're **one stack in a specific order**, because all three operate on the same parameter surface.

**The layer with customer-set thresholds is the foundation, and it exists today.** It's also deliberately our differentiation: every weight, decay rate, and threshold being visible and tunable — the glass box — is precisely what won the Tapestry engineering room against Dynamic Yield's black box. That control surface stays regardless of what we build above it.

**Verticals aren't a separate build — a vertical is a named configuration.** The engine is taxonomy- and config-driven: it scores whatever dimensions the catalog supplies, with per-dimension decay and weights. So "furniture retail" is a preset — consideration-cycle decay measured in days/weeks, dwell-weighted actions, dimensions like room/material/style — while "fashion" is minutes-to-days decay, view-frequency weighting, line/silhouette/occasion. We can ship vertical out-of-the-box cheaply *on top of* the layer, and the preset is a starting point the customer still tunes, so the glass-box story survives. We've already proven the mechanism in miniature: price-band affinity runs on a slower decay than product-line affinity today, because price posture moves slower than product interest — that's vertical knowledge expressed as configuration.

**The trained model is the destination — but the right architecture is learning that *fits the parameters*, not a black box that replaces them.** Once telemetry and outcomes accumulate, the system measures each customer's real half-lives and which behaviors actually predict conversion, and **proposes parameter changes into the same tunable surface** — human-approved, fully explained ("your furniture shoppers' measured consideration half-life is 9 days; your decay is set to 3 — apply?"). Runtime scoring stays deterministic and fast; the intelligence lives in fitting and proposing. This also solves cold start: a learned model needs data a new customer doesn't have — the vertical preset is exactly the prior you start from, and learning personalizes it over time.

**The flywheel:** each customer's learned parameters aggregate into ever-truer vertical presets, so the verticals get better the more customers run the product — a defensible asset a competitor can't copy from a spec sheet, because it's distilled from real cross-customer behavior.

**The one thing I'd rule out:** a black-box trained scoring model *at runtime*. It would surrender the exact positioning that's currently winning us deals against Dynamic Yield, re-create the problem customers are leaving them over, and break the latency/cost profile that makes the edge economics work (deterministic scoring is what keeps the unit cost at ~a tenth of a cent per visitor).

**The product-requirements implication:** the parameter surface *is* the product's API. Customers tune it (the layer), presets initialize it (verticals), learning fits it (the model), and the agent explains it. One surface, three product moments — shipped in that order because each one generates what the next one needs.
